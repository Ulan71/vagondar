# VagonDar — следующий этап: распознавание номеров вагонов камерой

> Статус: **идея / план**. Код ещё не начат. Документ от 08.11.2026.

## Цель

Сейчас оператор вручную создаёт событие (пригон/уборка) и вбивает номера вагонов.
Цель — чтобы **камера сама видела проходящий состав, создавала событие и добавляла номера всех вагонов**.
Оператору остаётся только проверить номера и проставить **направление** (предприятие).

## Как это будет работать

```
Состав проходит мимо камеры
        │
        ▼
[1] Камера (IP, RTSP-поток)
        │  видео
        ▼
[2] Сервис распознавания — на месте, на ПК рядом с камерой
        │  • заметил движение → начал «сессию» состава
        │  • на каждом кадре ищет табличку с номером и читает цифры
        │  • проверяет номер (8 цифр + контрольная цифра)
        │  • склеивает кадры: один вагон = один номер (голосование по кадрам)
        │  • состав прошёл (нет движения N секунд) → сессия закрыта
        │  JSON: время, номера по порядку, уверенность, фото номера
        ▼
[3] VagonDar API (Render):  POST /api/events/
        │  создаёт событие + вагоны (без направления, статус «на проверке»)
        ▼
[4] Оператор в VagonDar
        • видит новое событие с пометкой «с камеры»
        • сверяет сомнительные номера по фото
        • выделяет вагоны и проставляет направление пачкой
        • подтверждает событие → считается сумма, можно в Excel
```

**Почему распознавание на месте, а не на Render:** гнать видео в интернет дорого и медленно,
на Render нет видеокарты, а бесплатный тариф засыпает. На сервер уходит только результат
(номера + маленькие фото табличек) — это килобайты.

## Номер вагона и контрольная цифра

Номер грузового вагона — **8 цифр**, последняя — **контрольная**. Алгоритм:

1. Первые 7 цифр умножаются по очереди на веса `2 1 2 1 2 1 2`.
2. Если произведение двузначное — складываются его цифры (12 → 1 + 2 = 3).
3. Всё суммируется; контрольная цифра = `(10 − сумма mod 10) mod 10`.

```python
def wagon_check_digit_ok(number: str) -> bool:
    if len(number) != 8 or not number.isdigit():
        return False
    total = 0
    for digit, weight in zip(number[:7], (2, 1, 2, 1, 2, 1, 2)):
        p = int(digit) * weight
        total += p // 10 + p % 10
    return (10 - total % 10) % 10 == int(number[7])
```

**Проверено на текущей базе:** из 68 восьмизначных номеров алгоритм прошли **56**.
Не прошли (возможно, опечатки при ручном вводе — стоит сверить):
`29006321`, `29006336`, `29019282`, `51012873`, `74543454`.
Ещё 5 записей не 8-значные — похоже на тестовые данные: `67`, `11`, `12345`, `88003555355`, `123456432456754`.

Зачем это нужно для камеры: если OCR ошибся в одной цифре, контрольная цифра почти всегда это поймает →
номер сразу помечается «на проверку», а не уходит в базу молча. Эту же проверку стоит включить
и при ручном вводе (предупреждение, не запрет).

## Технологии (предварительно)

| Шаг | Варианты |
|---|---|
| Захват видео | OpenCV, RTSP с IP-камеры |
| Поиск таблички с номером | YOLO (Ultralytics), дообучить на своих кадрах |
| Чтение цифр (OCR) | PaddleOCR / EasyOCR; только цифры, 8 символов |
| Склейка вагонов | трекинг объектов (ByteTrack) + голосование по кадрам |
| Связь с VagonDar | HTTPS + токен в заголовке |
| Где крутится | мини-ПК на месте (желательно с NVIDIA GPU или Jetson) |

## Что поменять в VagonDar

**Модели**
- `TrainEvent`: `source` (вручную / камера), `status` (черновик / подтверждено).
- `Wagon`: `confidence` (уверенность распознавания), `photo` (фото таблички), `needs_review` (флаг «проверить»).
- Направление у вагона уже может быть пустым — интерфейс это умеет («нет направления, укажите»).

**API**
- `POST /api/events/` — принять событие с камеры (тип операции, дата/время, список номеров по порядку, уверенность, фото).
- Авторизация по токену (отдельный токен на каждую камеру).
- Защита от дублей: повторная отправка той же сессии не создаёт второе событие.

**Интерфейс**
- Метка «с камеры» и «на проверке» у события; фильтр «требуют проверки».
- Фото номера рядом с вагоном, сомнительные номера подсвечены.
- **Массовое назначение направления**: отметить галочками вагоны → выбрать направление → применить.
- Кнопка «Подтвердить событие».
- Подсказка направления по истории: если этот номер раньше ходил на «Е-порт» — предложить его.

**Инфраструктура**
- ⚠️ Сейчас прод на SQLite, и Render сбрасывает файлы при деплое/перезапуске.
  Пока вводит один человек — терпимо, но **данные с камеры будут приходить сами, и терять их нельзя**.
  Перед запуском камеры перейти на PostgreSQL (например, бесплатный Neon) — в README уже есть инструкция.

## Этапы

0. **Сбор данных.** Записать видео с камеры: 10–20 составов, день и ночь, разная погода.
   Без реальных кадров точность не оценить.
1. **Прототип оффлайн.** Скрипт: видеофайл → список номеров. Мерить точность на записях.
   Цель MVP: ≥ 95 % номеров верно, остальные помечены «на проверку».
2. **VagonDar: API + экран проверки.** Можно делать параллельно с п. 1, тестировать на фейковых данных.
3. **Реальное время на месте.** Сервис на мини-ПК, автозапуск, переотправка при обрыве интернета.
4. **Улучшения.** Тип операции по направлению движения состава, подсказка направления по истории номера.

## Открытые вопросы (уточнить перед стартом)

- Есть ли на месте интернет и место под мини-ПК с питанием?
- Как отличать пригон от уборки: по направлению движения или оператор выбирает?
- Бывают ли в составе вагоны без номера / с грязными, закрашенными номерами?
- Есть ли уже на путях считыватели RFID-меток вагонов (тогда часть задачи решается без камеры)?
